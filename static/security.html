Security & Trust

Enterprise-grade security. Zero-trust architecture.

Your financial data never touches a centralized server. Every artifact is cryptographically signed and independently verifiable.

Edge-First Architecture

All processing runs on Cloudflare Workers — 300+ global edge locations. Your CSV is parsed, reconciled, and packaged at the nearest edge node. Sub-100ms response times worldwide. No centralized server. No data at rest.

Cryptographic Integrity

Every close pack includes an HMAC-SHA256 signed manifest with SHA-256 hashes per artifact. Signing uses Web Crypto API with server-side secrets. Manifests use sorted keys for deterministic output. Any file modification breaks the signature chain.

Data Handling

CSVs are processed in-memory during the request lifecycle. No billing data is persisted after the close pack is generated. Close packs are stored in Cloudflare R2 as sealed, write-once objects. No delete operations — immutable by design.

Verification

Every close pack can be independently verified at finault.ai/verify. Upload your close pack ZIP — we recompute all SHA-256 hashes and validate the HMAC signature against our public verification endpoint. No trust required — verify yourself.

13-Step Request Security Pipeline

Every API request passing through Finault's gateway undergoes a rigorous 13-step security pipeline. This architecture ensures cryptographic validation, rate limiting, authentication, and input sanitization before any request reaches your data.

1

Module Initialization

Load 49 wired modules (security, billing, compliance) and establish baseline security context.

2

Error Tracking

Initialize Sentry-compatible error boundaries for incident detection and logging.

3

CORS Enforcement

Validate origin against allowlist (finault.ai, app.finault.ai, dashboard.finault.ai).

4

Request ID Generation

Assign unique request ID for full traceability throughout the entire request lifecycle.

5

Database Observability

Connect monitoring to Supabase with circuit breaker pattern for resilience.

6

IP Rate Limiting

KV-backed per-IP rate limits to prevent abuse and distributed attack patterns.

7

Authentication

Validate JWT or fk_ API key (SHA-256 hashed, never stored in plaintext).

8

Token Revocation Check

Cross-reference against KV revocation list for invalidated credentials.

9

Organization Rate Limiting

Apply per-org tiered rate limits based on subscription tier.

10

IP Allowlisting

Verify request IP against org's allowlist (if configured for enhanced security).

11

Replay Protection

Detect and block duplicate request IDs to prevent replay attacks.

12

Session Fingerprinting

Validate session integrity and detect anomalous access patterns.

13

Input Sanitization

Validate and sanitize request body before proxying to downstream services.
